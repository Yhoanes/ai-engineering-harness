# HARNESS v1.13.4

Tema: Executable Task Validator CLI

## Bug

Antes:
\python -m engine.validators.validate_task_contract <task>\
o ejecución directa del módulo
podía terminar sin validar porque no existía executable entrypoint.
El proceso podía devolver exit 0 aunque ninguna validación hubiera ocurrido.

## Resolution

Se añadió un wrapper CLI mínimo sobre:
\alidate(task: dict) -> ValidationResult\

No se duplicaron reglas.
No se cambió la API programática.

## CLI contract

Valid Task Contract:
exit 0
Task Contract validation: PASS

Schema or semantic validation failure:
exit 1
Task Contract validation: FAIL

Input/parsing error:
exit 2
Incluye:
- missing file;
- malformed YAML;
- wrong YAML root type.

Unexpected internal validator exception:
propagates normally with traceback/non-zero.
