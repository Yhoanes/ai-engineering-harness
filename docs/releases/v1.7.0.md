# AI Engineering Harness v1.7.0
## Physical Metadata Separation

This release completes the **second phase of the Harness 2.0 Foundation**.

- projects/ workspace is now strictly reserved for real software and user projects.
- Internal official governance metadata has been moved into the .harness/projects/harness-internal/ directory.
- **MetadataPaths abstraction** supports multiple aliases (harness-internal, .harness-internal, _harness-internal) and implements a fallback legacy detection layer with strict split-brain detection to protect data integrity.
- Residual, untracked local scratch data in the legacy workspace (projects/.harness-internal/scratch/) no longer blocks validation or constitutes governed metadata.
- 65 tracked metadata files have been cleanly migrated via 1-to-1 git renaming to preserve historical continuity.
- The HARNESS-0022 proposal artifacts are bit-for-bit preserved in the new untracked location.
- **Distribution boundaries** now explicitly exclude .harness/, protecting internal tracking data from leaking into bundled software exports.
- **Backwards compatibility**: .gitignore and source-of-truth.yaml do not enforce .harness/ for standard projects yet.

**Note:** v1.7.0 focuses exclusively on the Harness 2.0 physical separation foundation. The provider-neutral execution capability remains unreleased, and HARNESS-0022 execution is still frozen.
