# AI Engineering Harness v1.8.1
Explicit Execution Capability Semantics

This release provides a critical micro-correction over v1.8.0 to resolve the semantic ambiguity of empty collections in the execution capabilities contract.

## Changes
- **Explicit Scopes**: Introduced AccessMode (DENY_ALL, ALLOW_LIST, UNRESTRICTED) and a frozen ScopedAccess wrapper.
- **Empty Frozenset Ambiguity Eliminated**: Removed the undefined implicit states of empty sets. 
  - An empty set previously could imply "nothing is allowed" or "no restrictions apply". Now, DENY_ALL and UNRESTRICTED explicitly mandate empty sets, and ALLOW_LIST explicitly requires values.
- **Terminal Contradictions**: Rejection logic now guarantees that 	erminal_allowed=False pairs exclusively with DENY_ALL command scopes.
- **Workspace Bounds**: Defined that UNRESTRICTED in ead_paths or modify_paths strictly limits access within the boundaries of the workspace_root.
- **Forbidden Actions**: Preserved orbidden_actions as a pure set, as its negative semantic (blacklist) has no ambiguity.

## Status
- **Neutral Contracts Only**: This release strictly hardens the provider-neutral execution contracts published in v1.8.0.
- **No Multi-Provider Execution**: v1.8.1 does NOT enable multi-provider execution yet.
- **Legacy Unchanged**: The Antigravity legacy runtime and orchestrator remain unmodified.
- **HARNESS-0028**: The Antigravity provider wrapper remains pending/blocked.
- **HARNESS-0022**: Remains frozen.
