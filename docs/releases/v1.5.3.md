# Release v1.5.3 (Hotfix)

This release addresses a critical Context Loading defect discovered during the execution of `HARNESS-0022`.

## Context Loading Fix (HARNESS-BOOTSTRAP-0003)

During `HARNESS-0022`, it was identified that although governed artifacts (`proposals/<task_id>.md`) were successfully materialized physically into the `WorktreeSandbox` (fixed in v1.5.2), the `ContextLoader` was not injecting their contents into the `ContextBundle` and consequently not reaching the specialist's `final_prompt`. The agent received an abstract Task Contract description without the detailed architectural proposal, leading to an empty diff failure as it could not formulate the necessary tool calls.

The `ContextLoader` (`engine/context/loader.py`) has been updated to explicitly load both `tasks/<task_id>.yaml` and `proposals/<task_id>.md` into the `ContextBundle` at Context Level 2.

### Technical Details

- **Proposal Injection**: When `task_id` is provided at Level 2, `proposals/<task_id>.md` is seamlessly appended to `targets` and populated into `content_sections`, making it visible to `prompt_builder.py`.
- **Backward Compatibility**: If a proposal does not exist (for legacy tasks or tasks that do not strictly require one), the loader silently records it in `missing_sources` and execution proceeds normally without failing. Proposals are not mandatory.
- **Strict Isolation**: Proposals of other tasks are ignored.

### Exclusions
- `HARNESS-0022` (Añadir Testing Autónomo Gobernado) remains pending and is **not** included in this release.
