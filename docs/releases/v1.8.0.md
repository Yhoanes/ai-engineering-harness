# AI Engineering Harness v1.8.0
## Provider-Neutral Execution Contracts

This release initiates the **tercera fase de Harness 2.0 Foundation**, establishing the first formal provider-neutral execution boundary.

### Key Additions
- **ExecutionRequest**: A strictly typed and validated contract defining exactly what the Harness authorizes a provider to execute.
- **ExecutionResult**: The resulting semantic outcome from an execution, decoupled from the task's lifecycle.
- **ExecutionProvider Protocol**: The unified synchronous interface that any future execution engine (Antigravity, Codex, local runtimes) will implement.
- **ExecutionPurpose**: Formal semantics explicitly differentiating IMPLEMENT, TEST, and REVIEW workloads.
- **ExecutionIsolation**: A neutral isolation representation decoupled from specific sandboxing implementations.
- **ExecutionCapabilities & ProviderCapabilities**: Safe, immutable transport of the resolved Authority Matrix, preserving read/modify scopes, terminal access limits, and checking provider intrinsic abilities without hardcoding.

### Architectural Principles Enforced
- **Reported vs Verified Evidence**: eported_changed_files within the ExecutionResult is strictly treated as *provider-reported*. The Harness continues to be the absolute authority post-execution to independently verify physical evidence.
- **Context Boundaries**: The ContextBundle is delivered fully resolved. Providers do not execute MetadataPaths or interact with the .harness metadata root. 
- **Workspace Independence**: workspace_root definitively points to the user's isolated software repository, completely separated from internal governance state.
- **Extensible Provider Metadata**: provider_metadata accommodates provider-specific extensions (e.g., token usage) using defensive shallow copies.

### Current Limitations & Legacy Compatibility
> [!IMPORTANT]
> **v1.8.0 strictly introduces the contracts.** It does **NOT** yet introduce operational multi-provider execution.

- Contracts contain **zero** dependencies on Antigravity, Codex, or local tools.
- The existing Antigravity runtime (AutonomousRunner, WorktreeSandbox, etc.) remains operating under the legacy monolithic model and is **unmodified**.
- No provider is connected yet to the new Orchestrator route.
- The HARNESS-0022 test-execution proposal remains frozen.
