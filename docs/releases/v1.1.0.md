# Release v1.1.0

This release certifies the completion of the first major evolution cycle of the AI Engineering Harness, establishing its foundational capabilities for multi-agent workflows, state persistence, safe distribution, and structured authority mechanisms.

## Key Features & Architectures

* **Harness Evolution Advisor & Extension Architecture:** The system now incorporates a definitive architecture for safe self-evolution. Subagents and external tools can now securely query context, inspect diagnostic constraints, and propose structural updates to the Harness itself using the new Extensibility and Advisor capabilities.
* **Skills Foundation:** Integrated the Skills architecture allowing specific workflows and agent instructions to be maintained modularly, supporting rich conversational interfaces and domain-specific knowledge transfer.
* **Installer & Bootstrap:** A robust PowerShell-based installer (`install/setup.ps1`) now allows deterministic environment bootstrapping, preventing global pollution and automatically configuring symlinks, requirements, and execution policies.
* **Diagnostics:** A new diagnostic engine (`python -m engine.diagnostics`) performs deterministic evaluation of the Harness's operational health, verifying architecture constraints, dependencies, state transitions, and component linkages.
* **Backup & Distribution Export Engine:** The Harness can now autonomously generate its own certified deployment and backup artifacts. It safely partitions its own history, emitting `DEVELOPMENT.zip`, `PORTABLE.zip`, and `HISTORY.bundle` alongside cryptographic checksums and verifiable manifests.
* **Repository Hygiene:** Executed a comprehensive repository normalization cycle to eliminate internal friction, normalizing testing state, cache directories, and temporary extraction artifacts across execution environments.

## Bug Fixes & Refinements

* **Runtime Dependency Correction:** Resolved an architectural oversight where essential operational dependencies (e.g., `PyYAML`) were confined to the development context, causing isolation failures in Portable builds.
* **Dynamic Release Tag Identity:** The Export Engine now strictly inspects and requires explicit Git SemVer tags during extraction, replacing hardcoded artifacts with dynamic, source-of-truth semantic validation.

## Version Source-of-Truth Policy

The official Harness strategy mandates that the `VERSION` file and `pyproject.toml` (under `[project] version`) remain strictly synchronized as the sole source of truth for release identity. Dynamic packaging magic has been deliberately excluded to guarantee predictable offline distribution behavior and strict artifact parity. This is now enforced automatically via CI testing.
